### 原本の表示差に関する追補

総資本と純資産＋負債の不一致は既定で入力エラーとする。差の絶対値が1千円以内で、利用者が原本を照合して「原本の総資本記載値を採用」を選択した場合に限り、原本の総資本で計算を継続する。元の値・差・選択・確認状態を保存し、警告表示を残す。1千円超の差はこの選択で解除しない。この許容はアプリの原本確認手順であり、審査上の許容誤差を定めるものではない。

## 1. 目的と完了条件

入力した財務数値から計算した評点と、実際の経審通知書・経営状況分析結果を比較できるようにする。差が出た場合は、入力値・対象期間・計算過程・制度の違いを追跡できることを目標とする。

本改修の完了条件は次のとおり。

1. 対応範囲内のY点について、8指標・中間点数A・Y点を規定の端数処理で算出できる。
2. X2用の平均自己資本を選んでも、Y点に使う当期自己資本は変わらない。
3. 実績評点を年度・業種・制度情報とともに保存し、再読み込み後も照合できる。
4. 不足・推計・手動上書きを区別し、実績を転記しただけの一致を計算精度として数えない。
5. 固定した数値例と境界値テストに合格する。実資料の提供後、対象範囲内の過去3期を目安に検証し、未解決の差を一覧化する。

実資料が未提供の場合は「計算・機能検証済み／実績検証未実施」とする。「誤差ゼロ」「正式結果と一致」とは表示しない。

## 2. 対象範囲

### 2.1 第1段階で実装するもの

- 単独決算の法人、各期12か月の通常決算を対象とする詳細Y計算。
- 当期・前期の財務数値と、必要に応じた前々期のCF関連残高の管理。
- X2とYの入力分離、千円精度の保持、入力検証。
- 経審用営業CFの詳細計算と、算定済みCFの直接入力。
- Y点の計算過程表示と、X1・X2・Y・Z・W・Pの実績照合。
- 保存済みデータの移行、計算方式の識別、回帰テスト。

### 2.2 今回の対象外

- 工期・受注残・施工能力を反映する売上予測。
- 税引後利益・投資・借入・配当から将来の財務残高を積み上げる機能。
- 落札率の統計推定、確率分布による将来予測。
- 個人事業主、連結決算、創業直後、決算期変更、合併等の特殊経審の詳細計算。
- X1・Z・Wの全面的な再実装、過去の全制度への対応、自治体別の等級判定。
- 決算書PDFの新規OCR機能。追加財務項目は手入力で対応し、既存の経審PDF取込を拡張する。

対象外条件では資料保存と参照は可能とするが、詳細計算の結果を確定扱いにしない。旧制度のWが未対応の場合はW・Pの正式照合を保留し、条件が一致するY等のみ個別に照合する。

## 3. 現状と変更方針

以下は作成時点のコードを確認した結果である。

| 現状 | 改修内容 |
| --- | --- |
| `calcYFull`は支払利息のみを使用する | 受取利息・配当金を別項目として保持し控除する |
| 総資本売上総利益率に`equity + debt`を使う | 当期・前期の総資本を取得し、専用の平均総資本を作る |
| 決算書入力の2期平均自己資本が共通の`equity`に入る | X2用自己資本とY用当期自己資本を分離する |
| 営業CFの自動算定は利益・償却・税のみ | 運転資金等の増減を含む詳細計算を追加する |
| 詳細Yでも指標・Aの途中丸めがない | 丸め規則を共通関数に集約し、各段階の値を返す |
| 財務項目の反映時に万円単位へ丸めている | 原票と千円単位の値を保持する |
| 詳細入力が不足すると簡易Yへ切り替わる | 要求方式と実際の方式を常時表示し、詳細値の不足を明示する |
| PDFの参照評点は取込結果に保持されるが、年度データへの永続化がない | 実績レコードとして保存する |
| PDFのWを計算の上書き値として使う | 参照Wと計算Wを分け、上書きは明示した場合のみ採用する |

対象コード：`src/utils/calculations.js`、`src/components/YearPanel.jsx`、`src/App.jsx`、`src/utils/keishinPdfParser.js`、`src/components/KeishinPdfImport.jsx`。

## 4. 利用の流れと画面

### 4.1 利用の流れ

1. 対象の会社、決算期末日、業種、申請日、決算区分を設定する。
2. 当期・前期の決算数値を入力する。CFを詳細計算する場合は前々期残高も入力する。
3. X2の自己資本の採用方法と、CFの入力方法を選択する。
4. 「不足項目」「整合性エラー」を確認・修正する。
5. 詳細Yと8指標の計算過程を確認する。
6. 経審通知書等から実績評点を登録し、同じ条件の計算結果と比較する。
7. 実績照合用データを保存し、将来検討には別のシナリオを作成する。

### 4.2 財務入力

「当期」「前期」「前々期」の列を設ける。前々期はCFの詳細計算に必要な残高だけを表示する。単位は千円・万円を切替可能とし、入力済み値の意味は変えない。

入力欄の近くに「手入力」「資料から取得」「推計」「未入力」を表示する。ゼロは明示入力として受け付ける。空欄は未入力とする。

X2用の設定は以下を明示する。

- 自己資本：当期／2期平均／算定済み値の直接入力。
- 平均利益：2期から算定／算定済み値の直接入力。
- 選択値と当期の元データを両方表示する。

### 4.3 計算結果

Y点の横に「詳細計算」「参考推計」「入力不足」「対象外」のいずれかを表示する。

詳細計算の展開欄は次の列を持つ。

| 指標 | 使用した年度・入力値 | 算定前提 | 算定値 | 丸め後 | 範囲適用後 | Aへの寄与 |
| --- | --- | --- | --- | --- | --- | --- |
| y1～y8 | 分子・分母やCF内訳 | 平均・最低額等 | 丸め前 | 規定の桁数 | 上下限適用後 | 係数×値 |

内部キーは`y1`～`y8`とし、総合評点の構成要素X1・X2と混同しない。

詳細計算に不足があるときは、詳細Yを「—」とし、不足項目へのリンクを表示する。簡易Yは別枠の参考値として計算可能だが、詳細Yの欄に混在させない。詳細Yがない場合、詳細計算としてのPも「—」とする。

グラフは詳細計算・参考推計を凡例で区別し、未算定点をゼロとして描画しない。年度コピーで作った値や将来成長率からの値は、項目が揃っていても「参考推計」とする。

## 5. データ仕様

### 5.1 基本構造

シナリオ内に次のデータを持つ。以下の名称は実装上の推奨名称。

| 構造 | 主な内容 |
| --- | --- |
| `schemaVersion` | 新形式は2。旧形式1も読み込み対象 |
| `calculationVersion` | `legacy-v1`／`accuracy-v2` |
| `entity` | 内部会社ID、会社名、任意の許可番号、法人・単独等の区分 |
| `financialPeriods` | 期IDをキーにした財務実績。開始日・終了日・月数・実績/推計区分 |
| `assessment` | 対象期ID、業種、申請日、制度ID、X2・CF等の採用設定 |
| `referenceAssessments` | 対象期・業種別の通知書評点と資料情報 |
| `verificationCases` | 照合対象の入力スナップショット、参照実績ID、計算バージョン |

過去財務は将来シミュレーション用の`years`配列に追加しない。`years`には対象期への参照を持たせる。配列順から「前期」を推定せず、決算日の連続性を検証する。

### 5.2 金額と出所

金額の計算単位は千円。入力原文・元単位・換算後の値を保持する。千円整数の元データから平均を作る場合の0.5千円等は途中で捨てない。小数計算には十進演算または整数・分数演算を使う。

万円入力は小数第1位までで千円精度を表す。公式照合に用いる原票は、申請に使用した千円表示の財務諸表を基本とする。これより細かい値の入力は原文を保持し、「申請に用いた千円値」を確定するまで参考扱いとする。推計モードでは細かい値を保持できる。

各項目は少なくとも以下を保存する。

```text
value: 十進数文字列 または null
unit: thousandYen
sourceType: manual | pdfText | ocr | derived | estimate | legacy
verification: unconfirmed | confirmed
sourceId / page / sourceText: 資料との紐付け（取得できた範囲）
originalValue / originalUnit: 入力・取込時の値
updatedAt: 更新日時
```

OCRの確度と利用者による確認状態は別にする。OCRが「高確度」でも、それだけで確認済みにはしない。

## 6. Y点の計算仕様

### 6.1 8指標

金額はすべて千円。対象は第2章の通常決算とする。

| キー | 算式 | 数値の最小値 | 数値の最大値 |
| --- | --- | ---: | ---: |
| y1 | `(支払利息 − 受取利息配当金) / 売上高 × 100` | -0.3 | 5.1 |
| y2 | `負債総額 / (売上高 / 12)` | 0.9 | 18.0 |
| y3 | `売上総利益 / max(2期平均総資本, 30000) × 100` | 6.5 | 63.6 |
| y4 | `経常利益 / 売上高 × 100` | -8.5 | 5.1 |
| y5 | `当期自己資本 / 当期固定資産 × 100` | -76.5 | 350.0 |
| y6 | `当期自己資本 / 当期総資本 × 100` | -68.6 | 68.5 |
| y7 | `2期平均営業CF / 100000` | -10.0 | 15.0 |
| y8 | `当期利益剰余金 / 100000` | -3.0 | 100.0 |

算式の根拠：[CIIC掲載の国交省告示抄](https://www.ciic.or.jp/wp-content/uploads/2016/07/tebiki06-3.pdf)。最低総資本・上下限・ゼロ分母等の補足：[CIICの指標解説](https://www.ciic.or.jp/wp-content/uploads/2016/01/shihyou_y.pdf)。

### 6.2 端数処理と最終点数

1. y1・y3・y4・y5・y6は、割合を小数第5位まで四捨五入してから100倍する。y2・y7・y8は小数第3位まで四捨五入する。
2. 各指標の上下限を適用する。
3. 以下の係数でAを計算し、小数第3位を四捨五入して小数第2位までにする。
4. `167.3 × A + 583`を整数に四捨五入する。最終Yの範囲は0～1595とする。

```text
A = -0.4650*y1 - 0.0508*y2 + 0.0264*y3 + 0.0277*y4
    + 0.0011*y5 + 0.0089*y6 + 0.0818*y7 + 0.0172*y8 + 0.1906
```

根拠：[経営事項審査の事務取扱い・経営状況部分](https://www.ciic.or.jp/wp-content/uploads/2016/07/tebiki06-4.pdf)、[2026年改正掲載の通知全文・別紙1の5](https://www.mlit.go.jp/tochi_fudousan_kensetsugyo/const/content/001982607.pdf)。

負数の四捨五入をJavaScriptの`Math.round`任せにしない。十進のROUND_HALF_UP（ちょうど半分は絶対値が大きくなる方向）を共通仕様とし、負数境界を固定テストする。参照計算との照合で差が出た場合は、丸め箇所と規則を確認してから計算版を更新する。

### 6.3 ゼロ・負数・不足

| 条件 | 動作 |
| --- | --- |
| 売上高が明示的に0 | y1=5.1、y2=18.0、y4=-8.5。他の指標は通常どおり計算 |
| 固定資産0、自己資本＞0 | y5=350.0 |
| 固定資産0、自己資本≦0 | y5=-76.5 |
| 総資本0 | y6=-68.6 |
| 平均総資本が30000千円未満 | y3の分母を30000千円とする |
| 自己資本・利益・CF・剰余金が負数 | 有効値として保持し、各指標の規則を適用 |
| 売上・総資産・負債・固定資産等が負数 | 入力エラー。詳細計算しない |
| 必須項目がnull、空欄、非数、無限値 | 入力不足またはエラー。0やサンプル値に補完しない |
| 前期データが未入力 | 通常の2期平均は未算定。創業例外を推測して適用しない |

ゼロ分母の扱いは[CIIC指標解説](https://www.ciic.or.jp/wp-content/uploads/2016/01/shihyou_y.pdf)による。

### 6.4 営業CF

CF方式は「内訳から計算」「各期の経審用CFを入力」「経審用2期平均CFを入力」「簡易推計」の4種類とする。

```text
CF(t) = 経常利益(t) + 減価償却(t) − 法人税等(t)
      + Δ貸倒引当金 − Δ売掛債権 + Δ仕入債務
      − Δ棚卸資産 + Δ未成工事受入金
Δ = 当期末残高 − 前期末残高
平均CF = (CF(t) + CF(t-1)) / 2
```

対象勘定の定義は[経営事項審査の事務取扱い・5(7)](https://www.ciic.or.jp/wp-content/uploads/2016/07/tebiki06-4.pdf)による。一般のCF計算書の数値を自動的に経審用CFと同一視しない。

詳細計算では当期・前期の利益等と、当期・前期・前々期の対象残高が必要になる。対象外勘定も空欄のまま0とせず、0を入力する。算定済みCFの直接入力では対応する残高入力を必須にしない。

従来の簡易式は参考推計として残せるが、簡易式を使ったYは実績精度の集計対象外とする。

## 7. 実績照合

### 7.1 実績データと対応付け

実績は`companyId + periodEnd + industry + ruleSetId + referenceId`で管理する。再審査・訂正通知を想定し、同一期の複数資料を保存して採用資料を選べるようにする。

保存内容：会社識別、決算期、申請日、通知日、業種、制度ID、資料名、取得日時、X1・X2・Y・Z・W・P、任意の8指標・A、確認状態、資料出所。欠けた評点はnullとする。0点は欠損ではない。

制度IDは申請日と対応制度から決める。決算日だけで決定しない。2026年7月施行の制度改正があるため、過去実績を一律に現在のW計算へ照合しない。[国交省の改正案内](https://www.mlit.go.jp/tochi_fudousan_kensetsugyo/const/tochi_fudousan_kensetsugyo_const_fr1_000001_00088.html)

会社・決算期が不一致なら照合しない。業種不一致ならX1・Z・Pは照合しない。制度適合性は評点ごとに判定し、影響がないと確認済みの共通項目のみ照合可能とする。

### 7.2 比較表

| 項目 | 通知書実績 | 独立計算値 | 差 | シミュレーション採用値 | 判定 |
| --- | ---: | ---: | ---: | ---: | --- |
| X1／X2／Y／Z／W／P | 保存した参照値 | 上書き前の計算値 | 計算−実績 | 上書きを含む表示値 | 下記状態 |

判定は「一致」「差異あり」「入力不足」「条件不一致」「未確認資料」「参照値なし」「参考推計」とする。完全一致は差0のみ。1点差も差異として表示し、丸めの差と自動断定しない。

Pは次を分ける。

- `computedP`：上書き前の各評点から算出。精度評価の対象。
- `effectiveP`：利用者が明示的に採用した上書き評点を含む。シミュレーション表示用。
- `referenceP`：通知書の実績値。書換えない。

X1・Z2用の平均工事高を資料から入力することは入力データの利用であり、評点の上書きとは区別する。ただし平均値自体を再計算していないことを記録する。

### 7.3 差の説明

Yの差を選択すると、各指標とAを表示する。参照資料に8指標がある場合は指標単位でも差を表示する。Y点しかない場合は、不足項目・出所・期間の違いを示し、原因を推測で確定しない。

P差への寄与は、X1=0.25、X2=0.15、Y=0.20、Z=0.25、W=0.15を用いた丸め前の寄与として表示する。寄与の合計と整数P差の差は「最終丸め差」とする。構成評点が不足する場合は寄与合計を未算定にする。

### 7.4 複数期の検証

照合用入力は保存時点のスナップショットを持つ。将来計画のスライダー変更や成長率設定で過去の検証条件を書き換えない。「現在の入力で再検証」は別の検証履歴を作る。

評点ごとに対象件数、一致件数、一致率、平均絶対誤差、最大絶対誤差を表示する。母数は同条件・確認済み・独立計算可能な実績のみ。除外件数と理由を表示し、母数0は「未検証」とする。

異なる制度の実績、上書きで作った一致、未確認OCR、簡易推計を集計に含めない。計算バージョンが異なる場合は同一版で再計算するか別集計とする。

## 8. PDF取込

既存のテキスト抽出・OCRの結果を、計算入力候補と参照評点に分けて取り込む。

- 取込結果に会社・決算日・通知日・業種・単位・出所を追加する。取得不能はnullとする。
- 参照評点だけを検出したPDFでも、実績レコードを保存できるようにする。
- 通知書のWを取得しただけでは`wOverride`を自動有効化しない。
- 業種を特定できない工事高・Z、単位不明の金額は候補として表示する。全社値や先頭業種を確定値として代用しない。
- 当期工事高と2年・3年平均は別項目として保持する。平均値0も有効に指定できる。
- 読取結果を一覧に表示し、期間・単位・業種を確認して反映する。項目ごとに修正・除外できる。
- 読取依頼時のシナリオIDと対象期IDを固定する。別シナリオ・別年度への移動後に古い取込結果を反映しない。
- 取込のやり直しは参照資料の追加または明示的置換とし、既存実績の無言の上書きを防ぐ。

新規の外部送信先は追加しない。既存OCR連携を使う場合も、出所と確認状態の扱いはテキスト抽出と共通にする。

## 9. 保存と旧データ移行

1. 現在の自動保存、名前付きシナリオ、シナリオ複製・読込の全経路でschemaVersion 1→2を処理する。
2. 移行前データを保持する。新形式を保存・読取確認してから移行済みとする。保存失敗時は旧データを失わない。
3. `financialDoc`に当期・前期の原票値があれば、単位を確認して新しい期間データへ移す。
4. `equity`しかない場合は当期か平均かを決め付けず、旧値として保持する。`avgProfit`・`operatingCF`の期間も同様に扱う。
5. 旧比率から復元した利益金額や、旧スライダーのデフォルト値は推計扱いとする。追加項目の受取利息配当金等を勝手に0としない。
6. 既存のW上書きは旧シナリオの採用設定として保持するが、通知書実績レコードを捏造しない。
7. 移行済みデータを再読込しても再変換しない。移行は冪等にする。
8. 旧シナリオは`legacy-v1`で従来結果を再現する。新しい詳細計算へ切替時に差と不足項目を表示する。新規シナリオは`accuracy-v2`とする。
9. 未来年度へのコピーは実績資料・確認済み状態を引き継がず、推計として作成する。会社・期・業種が変われば照合条件も再判定する。

`calculationVersion`は計算方法、`ruleSetId`は適用制度として独立して管理する。保存形式の更新と制度改正を同一のバージョン番号で表さない。

以下は仕様検証用の合成例であり、実在企業の通知書ではない。金額は千円。CFは経審用に算定済みの値を直接入力する。

| 売上高 | 100000 | — |
| 売上総利益 | 15000 | — |
| 経常利益 | 6000 | — |
| 支払利息 | 800 | — |
| 受取利息配当金 | 200 | — |
| 純資産 | 30000 | 20000 |
| 負債総額 | 40000 | 30000 |
| 総資本 | 70000 | 50000 |
| 固定資産 | 28000 | — |
| 経審用営業CF | 3900 | 3100 |

### 11.3 実資料と画面の検証

- 対応範囲内の確認済み資料について、Y・8指標・Aを照合する。資料に存在する項目だけを評価する。
- 完全な入力と適合制度が揃った実績は整数評点の一致を目標とする。不一致を許容幅で隠さず、原因と対応状況を記録する。
- X1・X2・Z・Wに差があれば、入力・既存テーブル・制度のどこに差があるかを切り分ける。今回未修正のものは未解決として残す。
- `npm test`と`npm run build`を実行する。
- 画面で入力→詳細表示→実績取込→照合→保存→再読込を確認する。詳細不足、上書き、旧データ、未算定グラフも確認する。

## 12. 実装順序と後続段階

1. 財務データモデル・十進演算・移行処理・固定テストを作る。
2. 用途別の財務導出、CF、詳細Yを実装する。
3. 入力画面、計算過程、未算定時のグラフを実装する。
4. 実績永続化、PDF確認、比較・集計を実装する。
5. 回帰・画面検証とマニュアル更新を行う。
6. 実資料が揃い次第、過去実績で誤差を検証し差異を修正する。

第2段階は受注・工期・繰越・施工能力のモデル化、第3段階は利益・投資・資金調達に基づく将来財務の積上げとする。これらは今回の詳細Y計算を共通部品として利用するが、実績検証と将来予測の評価は分ける。
